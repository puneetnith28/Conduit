# Deployment Guide

Four ways to run Conduit, and one that does not work.

Read [Security](security.md) before exposing any of this to a network. Conduit runs coding
agents with real shell access.

---

## 1. Local

```bash
npm install          # .npmrc sets legacy-peer-deps: Strands wants Express 5, we use 4
npm run build
npm run start:all    # http://localhost:3200
npm run seed:demo    # so the console isn't empty
```

Two processes: the daemon on `:3210` (loopback) and the web server on `:3200`. Restarting
the web server does not kill your agents.

`npm run dev` runs both plus Vite on `:5173` with hot reload.

**Node 22 or newer.** Node 20 runs the app, but the unit suites use
`--experimental-strip-types`, which only exists from 22.6.

---

## 2. Desktop app

```bash
npm run build:desktop
```

Produces `dist-desktop/Conduit-Setup-1.0.0.exe` and a portable zip. The app bundles its own
daemon and web server — there is nothing to start separately.

`npm run check:desktop` runs 31 checks against the packaged build: it starts its own
daemon, loads `~/.conduit/.env`, runs every agent type, answers a Keeper turn with working
tools, opens a live voice session, refuses to open external links inside itself, and leaves
no orphaned process behind.

> **The installed app never sees the repo's `.env`.** It runs from its install directory,
> so `~/.conduit/.env` is the only config file it reads. See
> [Environment](environment.md#where-the-files-are).

Icons come from `build/icon.png`, regenerated by `npm run icons` from
`client/public/conduit1.png`. `build:desktop` runs that first.

## 3. Docker

```bash
export CONDUIT_AUTH=admin:pick-a-strong-password    # the compose file requires it
docker compose up -d --build
```

The image installs all six agent CLIs plus `aider` (via `uv` on Python 3.12 — aider needs
`>=3.10,<3.13`), `curl` and `git`.

Agents still need to be logged in. Either mount your existing logins — the compose file
already mounts `~/.claude`, `~/.codex` and `~/.gemini` — or:

```bash
docker compose exec conduit claude login
docker compose exec conduit node scripts/seed-demo.mjs
```

Your code goes in `./workspace`, mounted at `/workspace`. **Project paths must point at
`/workspace/...`**, not a host path — the container cannot see your filesystem otherwise.

```bash
docker compose logs -f conduit
docker compose down          # -v also deletes Conduit's data
```

## 4. EC2

`t3.small` or larger.

```bash
sudo yum install -y docker git && sudo systemctl start docker
git clone <repo> && cd Conduit
export CONDUIT_AUTH=user:strong-password
docker compose up -d --build
```

| Setting | Value |
|---|---|
| Port 3200 | Open **only** to addresses you trust, or behind a TLS proxy |
| Port 3210 | Closed |
| IAM instance role | `bedrock:InvokeModel` on exactly the model in `BEDROCK_MODEL_ID` — see [`docs/bedrock-iam-policy.json`](bedrock-iam-policy.json) |

Basic auth over plain HTTP sends the password with every request. Put TLS in front of it.

**Terminate the instance when you are done.** A public Conduit is a shell on that box for
anyone who gets in, and the daemon's `/org/*` endpoints are unauthenticated on loopback.

## What does not work: serverless

Conduit's backend **cannot** run on Vercel, Netlify Functions, Lambda, or any
function-per-request platform:

| Conduit needs | Serverless gives |
|---|---|
| `node-pty` spawning real terminals | No PTYs |
| A daemon that lives for hours owning those processes | Functions die in seconds |
| Persistent WebSockets | Not supported per-request |
| Filesystem state in `~/.conduit` | Ephemeral |
| Two processes, one on a loopback port | One function per request |

**The landing page is a different story.** It and the animated demo make no API calls at
all, so they deploy as static files:

```bash
vercel --prod
```

[`vercel.json`](../vercel.json) already sets `outputDirectory: dist/client`. Verified with
no backend running: hero, demo, footer and all eight nav items render with zero uncaught
exceptions. `/#console` degrades to an empty console shell rather than a blank page.

That gives you a live link where someone can watch the whole workflow — including an
approval gate stopping a force-push — with nothing installed.

## Health

```bash
curl -s localhost:3200/api/health | jq .supervisorHealth
```

```json
{ "state": "ok", "provider": "bedrock", "model": "us.anthropic...", "strands": true }
```

| Field | Meaning |
|---|---|
| `state` | `ok`, `degraded` (working, not on the configured provider), `failing`, `idle`, `off` |
| `provider` | Which one actually answered |
| `strands` | Whether it went through the Strands SDK |

`GET /api/daemon/status` tells you whether the web server can reach the daemon — the first
thing to check if the UI loads but nothing works.

`npm run check:bedrock` distinguishes a missing IAM permission from a model the account
never enabled from a quota cap. All three surface as `AccessDenied` or a bare 429.
